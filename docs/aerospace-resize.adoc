// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

The dimension to resize is chosen by the first argument

* `width` changes width
* `height` changes height
* `smart` changes width if the parent has horizontal orientation, and
it changes height if the parent has vertical orientation
* `smart-opposite` resizes the opposite axis of smart

For floating windows, the window is resized around its centre and kept inside its monitor.
`smart` changes the longer side and `smart-opposite` the shorter side, keeping the aspect ratio.

For tiled height changes, the target and its donors respect
`minimum-window-height` (200 macOS display points by default). Inner vertical
gaps shrink first when the requested floors do not fit. If the container is
still too short, its bounds win and every tiled frame receives a positive
share.

Second argument controls how much the size changes

* If the `<number>` is prefixed with `+` then the dimension is increased
* If the `<number>` is prefixed with `-` then the dimension is decreased
* If the `<number>` is prefixed with neither `+` nor `-` then the command changes the absolute value of the dimension

// =========================================================== Options
include::./util/conditional-options-header.adoc[]

-h, --help:: Print help

--window-id <window-id>::
include::./util/window-id-flag-desc.adoc[]

--independent::
Change the width without taking it from, or giving it to, the neighbouring windows.
The layout as a whole becomes wider or narrower instead and stays centred.
This needs `adaptive-layout`, a layout that has free space beside it, and a target that is a top-level column.
When growing has no free space left to use, and in every other case, the flag changes nothing and the neighbours give or take the width as usual.
The layout keeps its new width until its number of columns changes or `balance-sizes` runs.
