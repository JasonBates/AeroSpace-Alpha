# AeroSpace Alpha v0.8

Alpha v0.8 brings the build onto upstream `main` through
[`c960a8ac`](https://github.com/nikitabobko/AeroSpace/commit/c960a8ac).
It retains adaptive widescreen layouts, Focus Mode, cross-monitor focus,
floating-window controls, monitor recovery, workspace events and the optional
focused-window border. Alpha is developed while waiting for upstream fixes;
the [README](https://github.com/JasonBates/AeroSpace-Alpha/blob/v0.8/README.md)
lists them and credits their authors.

## Window identity

The build adopts Nikita Bobko's upstream logical window identity and invisible
window model. A window keeps its AeroSpace `window-id` and place in the layout
when a native Finder or Ghostty tab changes, even though macOS may assign the
replacement tab a new `window-native-id`. Invisible native Spaces and inactive
tabs keep their layout position without taking visible space. Alpha's former
[#2225](https://github.com/nikitabobko/AeroSpace/pull/2225) object-replacement
implementation is retired. Adaptations of
[#2317](https://github.com/nikitabobko/AeroSpace/pull/2317) and
[#2326](https://github.com/nikitabobko/AeroSpace/pull/2326) still protect
windows when Accessibility enumeration times out or an app stops responding.

The new optional `launch-window` command captures a destination workspace
before an external app adapter creates a window. Its companion launch helper
remains experimental and is not enabled in the daily setup.

## Known launch limit

In native trials, new Ghostty and Finder windows sometimes showed a brief
first frame on a different monitor before AeroSpace placed them on the
requested workspace. That flash is accepted for this release. The command
controls AeroSpace's first managed placement, not an app's first native frame;
it makes no zero-flash promise across apps or monitor setups.

## Validation

The current core passed 680 Swift tests, the repository's exact `./test.sh`,
independent source review and universal release-package validation. The
separate companion configuration and helper suite passed 70 tests. Lifecycle
simulations cover many window and layout transitions, but they do not run
native Accessibility or window-server event delivery. A hands-off launch
trial checked placement and settled focus for Ghostty and Comet across three
displays, and a separate Finder trial checked stable placement and focus.
The complete native lifecycle and display checklist remains unperformed;
[migration validation](https://github.com/JasonBates/AeroSpace-Alpha/blob/v0.8/docs/migration-validation.md)
records the evidence and
its limits.
